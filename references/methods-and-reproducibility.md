# 算法讲解与可复现性核查

用于解释算法、公式、实现及复现范围。沿论文问题讲清输入怎样成为结果，不把汇报扩成算法课程。下列数值均为自拟教学数据，不是论文实测结果。

## 1. 沿研究问题讲方法

沿“现象 → 问题 → 分析 → 结果”推进，方法紧邻对应结果。听众应能回答：输入什么、输出什么、怎样读本图。

| 讲述环节 | 应回答的问题 | 避免的跳步 |
|---|---|---|
| 当前问题 | 作者现在想比较、预测或解释什么？ | 开头直接报算法缩写 |
| 简单方法与需求 | 直接看比例、单基因或简单模型，哪些信息还没有回答？ | 未做比较就声称普通方法不行 |
| 观测与输入 | 一行是谁？一列是什么？数值经过什么处理？训练时有哪些标签？ | 只说“输入单细胞数据” |
| 学习与输出 | 哪部分需要训练？输出给每个细胞、样本、患者还是基因？ | 把表示学习、分类和解释混为一步 |
| 小例子 | 用最少数字展示一次具体变换或预测 | 假装三五个数字训练了论文大模型 |
| 公式 | 先讲关系，再定义每个符号、求和方向和分母 | 把整段推导塞进结果页 |
| 实现与验证 | 作者实际调用什么？怎样划分数据？用什么检查输出？ | 用最新版默认参数代替论文版本 |
| 生物学读法 | 本图支持什么、尚不能推出什么？ | 把模型分数当成实测功能或因果效应 |

若作者未说明为什么选某个方法，使用三种明确措辞：

- **作者陈述**：“Methods明确写明，为了……采用……”，提供定位。
- **方法性质与工程推断**：“结合这一任务，该方法的……性质可能有帮助”，说明这是讲解者推断。
- **待验证建议**：“可以比较……”，给出验证设计，不称为论文已完成的改进。

“作者选择了X”不等于“作者证明X最好”。树模型便于表示条件组合，但不能由此断言线性模型、随机森林或神经网络都无法完成相同任务。

例如解释XGBoost＋SHAP的选择时，可说：树便于学习“A高且B低”这类条件组合；TreeSHAP利用树结构，在相应特征依赖假设下较高效地分摊预测贡献。这是结合任务的方法性质解释，是否为作者明示理由仍须查原文。SHAP不绑定XGBoost，其他树、线性及部分深度模型也有相应解释器，支持范围和近似性质各异。没有同任务benchmark，不称该组合最佳。参见[XGBoost模型说明](https://xgboost.readthedocs.io/en/stable/tutorials/model.html)与[SHAP解释器目录](https://shap.readthedocs.io/en/latest/api.html)。

## 2. 先核实，再简化

### 2.1 四层证据分开记录

1. **本文明确内容**：原文Methods、Results、图注、补表及更正。记录PDF物理页与小节，必要时同时记录印刷页码。
2. **本文实际实现**：作者仓库的指定commit、脚本或notebook、函数与参数、保存输出。notebook注明cell编号从0还是1开始；保存输出只能证明文件记录过该输出，不能证明本次执行成功。
3. **软件标准原理**：与论文版本对应的官方方法论文、文档和源码。当前文档可帮助解释，但版本不一致时不能据此断言作者当时的默认设置。
4. **教学简化或新方案**：自拟数值、简化式、概念伪代码、替代模型提案。显式标识，不能混入论文实测数字。

依次核对论文说明、实际调用和对应版本定义。原文、代码、保存输出冲突时分别定位；不静默选一个，不把模板缺陷直接判成论文结果错误。

关键方法记录至少包含：问题；证据类别；输入单位/形状/处理/标签；输出单位/形状/尺度；计算与阈值；代码定位及版本；划分与验证；结论边界。

### 2.2 只简化表述，不改变计算对象

- “程序权重×表达”可以帮助介绍线性组合，但不能替代实际采用回归t统计量的评分方法。
- “表达≈活动量×权重”可说明因子分解的直觉，不能冒充包含先验图、约束及其他项的完整训练目标。
- 输入基因集数、功能类别数、学习因子数、保留因子数、候选基因数分别属于不同阶段，不要求彼此相等。
- 布尔成员表能说明是否入选，不能恢复连续权重。反过来，也不能因为没有权重就声称公开补表完全没有先验清单。
- 正文使用易读的中文关系式；讲稿保留完整公式和来源。若导出环境不能可靠显示LaTeX，另备无歧义的纯文本式，例如 `t = 斜率 / 斜率的标准误`。

### 2.3 不盲从未经核实的不足

例如`|log2FC| > 1.5`对应倍数大于`2^1.5≈2.83`或小于约`0.354`；两倍上调对应log2FC=1。阈值较严不是自动缺陷：先查作者希望筛出什么效应、表达量和样本支持，再建议阈值敏感性分析。p值/FDR与效应阈值分别核对，不能因为用户提出质疑就补造方法错误。

## 3. 让统计单位和矩阵形状始终可见

常见对象如下，不是必经流程。`n`为细胞数，`G`为基因数，`d`为表示维数，`M_c`为含类型c的患者/样本数，`P`为程序数，`K`为类别数。

| 对象 | 典型形状 | 必须交代 |
|---|---|---|
| 单细胞表达 | `n × G` | raw counts、归一化、log或模型校正值；基因身份和顺序 |
| 细胞表示 | `n × d` | 坐标由哪份模型产生；坐标不是逐个基因表达 |
| 某类型的pseudobulk计数 | `M_c × G` | 是否按样本求和；不能把表达均值冒充计数求和 |
| 某类型的平均表达或程序分数 | `M_c × G`或`M_c × P` | 先求均值还是先取log；在哪个范围标准化 |
| 某类型的患者表示 | `M_c × d` | 按哪些ID聚合、最少细胞数、缺失类型怎样处理 |
| 分类输出 | `n × K`或`M_c × K` | 对细胞还是患者预测；输出是margin、概率还是类别 |

患者、样本和细胞数不互换。一个患者可有多个组织或时间点；样本不自动是独立患者。聚合细胞可减少伪重复，但不自动解决纵向重复、配对组织或研究混杂。

metacell通常聚合相似细胞，pseudobulk常按生物学重复聚合；核对是否跨患者/类型、求和还是均值。更多metacell不等于更多独立患者。

混合模型中，研究随机截距处理的是研究层相关性；它不等于患者随机截距。固定项、随机项、健康参照、交互项及多重比较范围都要按该研究核实，不能自动补入年龄、性别或治疗变量。

## 4. 三个可复算的教学例子

按需要选择，正文、讲稿和阅读资料保持同一组数值。这是数学教学，不是论文复现。

### 例一：SHAP加回的是哪一种模型输出？

**问题**：某条记录的模型分数为何升高？这个分数是否就是患病概率？

给定一个已经训练好的二分类教学模型，原始分数为：

```text
m(A,B) = 0.2 + u(A) + v(B)
u：A高时+0.6，A低时−0.6
v：B高时+0.1，B低时−0.1
```

设解释背景包含A、B高低的四种组合，各占四分之一；此教学背景中两特征独立。解释A高、B高的记录。未知特征按该背景取平均，得到：

| 已知道的特征 | 背景平均后的原始分数 |
|---|---:|
| 都不知道 | 0.2 |
| 只知道A高 | 0.8 |
| 只知道B高 | 0.3 |
| A、B都知道 | 0.9 |

两个特征只有两种加入顺序，分别算边际增量后平均：

```text
φ_A = [(0.8−0.2) + (0.9−0.3)] / 2 = 0.6
φ_B = [(0.3−0.2) + (0.9−0.8)] / 2 = 0.1
m = 基线0.2 + φ_A + φ_B = 0.9
```

`φ`是对**所选输出空间**的贡献；基线是背景下的模型期望。本例基线碰巧等于初始常数，不是一般规定；未知特征也不等于置零或基因敲除。

若该二分类模型使用logistic链接，则：

```text
p = 1 / (1 + exp(−m))
m = 0.9 → p ≈ 0.711，即71.1%，不是90%
```

不把各margin贡献分别转概率再相加。多分类需结合全部类别分数，不能照搬二分类式。若解释概率空间，加和才对应概率；核对`model_output`、背景、类别轴和版本。[TreeExplainer官方文档](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html)说明了输出空间、依赖假设和加和校验。

**生物学边界**：解释模型不等于证明致病。SHAP不一般等于叶子值；本例加性结构仅便于手算。

### 例二：weighted F1为何不是“分对了多少”？

**问题**：多数类分得较好、少数类漏得多时，一个总分怎样概括？

以下是20位独立测试患者的**教学预测**，行是真实类别，列是预测类别：

| 真实类别 | 预测A | 预测B | 真实数量support |
|---|---:|---:|---:|
| A | 13 | 2 | 15 |
| B | 4 | 1 | 5 |

把每一类轮流看作“本类”，定义：TP为正确找出的本类，FP为误叫成本类的其他类，FN为被漏掉的本类。

```text
精确率 = TP / (TP+FP)
召回率 = TP / (TP+FN)
F1 = 2TP / (2TP+FP+FN)
```

- A：`TP=13, FP=4, FN=2`，所以`F1_A=26/32=0.8125`。
- B：`TP=1, FP=2, FN=4`，所以`F1_B=2/8=0.25`。
- 按真实数量加权：`WF1=(15/20)×0.8125+(5/20)×0.25=0.671875`。
- 正确率是另一项计算：`accuracy=(13+1)/20=0.70`。

WF1=0.672不是“67.2%患者被分对”。展示每类表现以避免掩盖B类低召回。权重来自真实support，不自动让类别或患者等权。[scikit-learn官方定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html)提供公式和`average`选项。

**对应真实研究时**：先核对support计的是细胞、样本还是患者，以及是否另设`sample_weight`。细胞级WF1即使按患者划分了测试集，也仍不是患者级诊断准确率。

### 例三：ULM分数为什么不是“表达乘权重相加”？

**问题**：固定一个样本和一个程序，程序权重较高的基因，是否也倾向表达较高？

只为展示含截距的一元最小二乘计算，给定五个已对齐基因的权重`w`和处理后读数`y`。这些数值不代表任何文章的真实基因权重，也不替代其表达预处理。

| 基因 | w | y | 预测值ŷ | 残差y−ŷ |
|---|---:|---:|---:|---:|
| G1 | 0 | 1 | 1.0 | 0.0 |
| G2 | 1 | 2 | 1.6 | 0.4 |
| G3 | 2 | 1 | 2.2 | −1.2 |
| G4 | 3 | 4 | 2.8 | 1.2 |
| G5 | 4 | 3 | 3.4 | −0.4 |

模型为`y_g = a + βw_g + ε_g`。一个点是**基因**g；`a`是截距；斜率`β`表示权重增加1时拟合读数增加多少；`ε`是未解释的偏差。这是在固定样本内跨基因回归，不是五位患者。

```text
w均值 = 2；y均值 = 2.2
Sxx = Σ(w−2)² = 4+1+0+1+4 = 10
Sxy = Σ(w−2)(y−2.2) = 2.4+0.2+0+1.8+1.6 = 6
β̂ = Sxy/Sxx = 0.6
â = 2.2−0.6×2 = 1
```

帽子表示估计值，`Σ`沿五个基因求和。代回`ŷ=1+0.6w`得到预测值，再算误差与斜率的不确定性：

```text
SSE = Σ(y−ŷ)² = 0+0.16+1.44+1.44+0.16 = 3.2
自由度 = 5−2 = 3
SE(β̂) = √[(SSE/3)/Sxx] = √[(3.2/3)/10] ≈ 0.3266
t = β̂/SE(β̂) = 0.6/0.3266 ≈ 1.84
```

自由度减2对应估计了截距和斜率。标准误表示斜率在模型假设下的不确定性，不是表达标准差。t兼顾斜率和不确定性；0.6或`Σwy=28`均不是这里的ULM分数。

[decoupler v1.9.2的ULM说明](https://decoupler.scverse.org/en/v1.9.2/generated/decoupler.run_ulm.html)将分子读数作为响应、网络权重作为解释变量，并返回拟合t值。实际使用需核对截距、表达层、标准化范围、基因交集、无关联权重的处理及最少靶数；不要把本例五个基因的设置套进所有版本。基因相关性和网络选择也影响统计解释，活动分数不是直接测得的通路流量。

## 5. 这些方法边界要保留

### scVI/scANVI：技术与生物差异不是保证可分

先说具体任务：跨批次比较细胞、估计条件化表达，或辅助细胞类型预测。scVI从计数及注册的批次/协变量学习潜在表示与生成模型；scANVI加入可用的细胞类型标签，具体模型见[scVI](https://docs.scvi-tools.org/en/stable/user_guide/models/scvi.html)和[scANVI](https://docs.scvi-tools.org/en/stable/user_guide/models/scanvi.html)官方说明。

初学者可以这样理解：“编码器把表达压成坐标；生成模型结合坐标、测量条件等解释观测计数；训练后读取坐标，或在指定条件下估计表达。”这是流程直觉，不是完整目标函数。

核对计数分布、标签/批次/协变量列、维数及条件化输出方式。坐标、校正表达和类型预测不是同一输出。同名模型也可能有不同特征、标签、结构与用途。

疾病与研究完全重合时，不能保证正确分离；过强混合也可能抹去状态。技术混合与生物结构须同时检查，说明指标方向和汇总范围。UMAP混合不等于混杂已解决。

### SCimilarity与XGBoost：保留用户指定的比较任务

用户要求模型比较时，不擅改成注释或映射流程比较。先列输入、训练监督、结构和输出：[SCimilarity](https://github.com/Genentech/scimilarity)学习细胞表达表示并支持相似细胞搜索等任务；XGBoost在指定特征和标签上学习树模型。表示、类型标签、疾病标签和疾病分数不能互换，也不能把SCimilarity自动称为Transformer。

疾病任务可比较“表达＋XGBoost”与“冻结SCimilarity表示＋同规格XGBoost”，必要时各加线性模型以区分表示与分类器贡献。统一疾病标签、患者划分、评价对象、调参预算和外验。报告预训练数据/容量并排查测试重叠；冻结不等于无泄漏。

这是待验证方案，不是更优结论。输入改为坐标后，SHAP解释坐标维度，不自动得到基因排名。

### Spectra与SCENIC：回答不同问题

- [Spectra](https://github.com/dpeerlab/spectra)使用表达、功能基因集先验及相应设置中的细胞类型信息，学习基因程序及其活动。说明先验、连续权重、输出marker名单和后续程序评分的区别；不要预设所有因子都是固定通路或每个先验只对应一个因子。
- [SCENIC](https://scenic.aertslab.org/)从共表达候选和序列基序等信息组织调控单元，再评估其活性。它不是完全无先验地从零发现调控。TF自身RNA、候选靶基因活性和真实结合/扰动效应是不同证据。

都有基因集合不等于任务相同，候选网络不等于因果。GENIE3/GRNBoost2、先验和版本按实际实现核实。

## 6. 验证设计：训练、适配、测试分别说清

列明各队列用于训练、选特征、调参、定阈值、无标签适配还是最终评价，再检查：

1. **隔离单位**：目标是泛化到新患者，就按患者隔离；同一患者的细胞和重复样本不能随机分到训练与测试两侧。新研究/新中心泛化需要相应层级的独立测试。
2. **训练折内选择**：用结局标签选基因、阈值或模型时，不得先看全部测试标签。归一化、缩放、缺失填补和降维也需说明在哪些数据上拟合；独立外部固定先验与使用本队列标签筛出的名单不同。
3. **无标签适配**：若方法允许利用query表达适配，明确这是包含测试协变量的适配设计，不能称完全未见测试数据；最终标签仍封存，所有对照遵守相同允许规则。严禁利用测试结局调参。
4. **表示一致性**：下游分类器训练用的参考坐标和待预测query坐标应处在相容的模型空间；若更新了表示模型，需要核查参考坐标与分类器如何同步。
5. **外部重训与迁移**：在外部数据重新训练分类器后表现较好，支持特征或方案的可用性；不等于原模型直接迁移成功。分别报告直接预测、无标签适配、监督微调和完全重训。
6. **指标与不确定性**：报告类别支持数、混淆、每类表现、拒判规则及适合的汇总指标。若观测嵌套于患者，置信区间或重采样应尊重相应独立单位；小细胞级P值不替代患者级证据。

投票要说明投票者是细胞、细胞类型还是模型。唯一最高票是相对多数，不一定超过半数；并列、缺失类型和未知类别的处理不能由讲解者临时补造。

## 7. 可复现性：先证明拥有什么，再决定能运行什么

### 7.1 不使用含糊的“源码和数据已全部下载”

区分仓库文件齐全与分析输入齐全。ZIP下载成功不证明子模块、LFS对象、外部模型和数据都存在。

在任务范围内建立清单：

| 类别 | 应记录的证据 |
|---|---|
| 仓库 | URL、分支/tag、commit、是否有本地修改；若只取得archive，记录下载入口与校验值 |
| 子模块 | 是否声明子模块、递归版本、是否初始化并可读 |
| Git LFS | 是否使用LFS、文件是pointer还是实际对象、声明大小与实际对象是否匹配 |
| 数据 | accession/DOI、文件清单、大小、发布者校验值、访问状态、格式与矩阵维度 |
| 模型/中间产物 | 权重、基因顺序、标签字典、先验、手工筛选表、归一化参数、预计算结果 |
| 环境 | 语言与包版本、锁文件/容器、参考数据库及基因注释版本、种子、硬件需求 |

可用只读命令确认已取得的Git内容，例如`git rev-parse HEAD`、`git status --short`、`git ls-files`、`git submodule status --recursive`。仓库使用LFS且工具可用时再检查`git lfs ls-files -l`及实际文件内容。没有检查或工具不可用时写“未核实”，不能填成“无缺失”。

数据状态分为：**本地已校验、公开但未下载、受控申请、仅描述未定位、未随该版本提供**。repo未附不等于作者未公开，还需查补表及数据/模型仓库。

先读元数据、索引、小表和文件头，选择最小有效复核。不自动扩展为巨量/受控/收费下载或全局安装。超出授权时，先说明具体资源、体积/算力与验证目标。

### 7.2 静态审查与实际运行分开

运行作者代码前，检查删除/移动命令、硬编码输出路径、覆盖写、外部提交、网络访问及pickle等不可信反序列化风险。优先在隔离的输出目录、复制的配置和已确认的输入上执行低资源步骤，不把作者路径直接照抄到本机。

逐主干记录输入、输出、依赖和人工步骤。重复notebook可按代码哈希归组，说明代表变体；不声称逐字审遍重复输出。从保存输出恢复列表不等于重跑生成流程。

估计下载/解压体积、稀疏数组及密集副本内存、并行进程和显存。调度脚本申请的CPU/RAM/GPU是申请量，不是已证明的最低需求。

### 7.3 用四个完成层次报告结果

| 层次 | 实际完成的事情 | 不应升级的宣称 |
|---|---|---|
| 静态方法审计 | 阅读论文、代码、配置、依赖与保存输出 | “模型已经复现” |
| 复图/结果复核 | 从发布表或保存中间产物重画图、复算汇总量 | “从原始数据得到同样发现” |
| 核心复算 | 从明确的真实输入重新执行关键统计或训练步骤 | 未运行的上游、其他队列和整套流程也已完成 |
| 全流程复现 | 从声明的起始数据到最终结果均执行并核对 | 超出指定commit、数据版本、参数和验证范围的普遍保证 |

记录起始输入、命令/环境、结果、基准与容差。随机结果比较需指明数字、排名、方向或结论。模拟测试只验证程序，不叫论文复现。

报告已核对内容、缺口和可复现范围。“理论可运行”不写成“已成功”。

## 8. 交付前的短检查

- 观测单位、矩阵形状、标签用途、输出空间和求和方向是否一致？
- 教学值是否明确标识，算术是否实际检查，是否误称为作者估计？
- p值、校正p值、效应量、活动分数、概率和SHAP贡献是否混用？
- 训练、选择、query适配、外部验证与测试是否分清？
- 一页合并后是否保留原图可读性，讲稿是否仍含失效的“上一页/下一页”或方位？
- 公共技能仓库是否仅包含自写指南、泛化例子及公共来源链接，而无论文源图、聊天记录、患者信息、本机绝对路径或访问凭据？

这些检查服务于当前汇报问题。不要为了显得全面而不断追加算法、审计项目或未经要求的巨大下载。
